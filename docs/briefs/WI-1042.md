# WI-1042 - Validate manual measurements
## Goal and context
Radiologists add measurements via POST /api/studies/{id}/measurements. Bad input causes 500s
(MeasurementService.Add: Enum.Parse on organ; decimal divide by SliceThicknessMm). Contract
(docs/api-contract.md) requires ProblemDetails 400 and "bad input must never produce 500".
## Scope
In: server-side validation of organ, kind, unit, value, sliceThicknessMm; 400 ProblemDetails with errors.
Out: legacy app; UI error display; analysis calculations; new NuGet packages.
## Acceptance criteria (Given / When / Then)
AC1 Given organ not supported / empty, When posting, Then 400 with errors.organ (organ case-insensitive)
AC2 Given organ not in the study, Then 400 with errors.organ
AC3 Given kind not valid for organ (see domain-glossary.md), Then 400 with errors.kind
AC4 Given unit not matching kind, Then 400 with errors.unit
AC5 Given value outside the glossary range, Then 400 with errors.value (Liver MeanDensity may be negative)
AC6 Given sliceThicknessMm <= 0 or > 10, Then 400 with errors.sliceThicknessMm
AC7 Given a valid measurement, Then 201 (unchanged)
## Assumptions and open questions
- Max slice thickness 10 mm: from the contract example — confirm with product.
- Should the UI show the field errors? (separate work item)
## Constraints and risks
No PatientName in logs or responses. Synthetic data only in tests.
